# TeamFinder - система подбора участников в команду

## Назначение

TeamFinder помогает создавать проектные команды, публиковать необходимые роли
и обрабатывать заявки кандидатов. Консольная объектная модель из ПР3 сохранена и
дополнена базовым веб-интерфейсом на Django 5.2 в рамках ПР5.

Целевая аудитория проекта: студенты, участники хакатонов, разработчики и
руководители команд, которым нужно найти участников на конкретные роли.

## Объектная модель

| Класс | Основные атрибуты | Поведение |
| --- | --- | --- |
| `User` | `id`, `name`, `email`, `stack`, `experience` | создание из JSON, преобразование в JSON |
| `Role` | `name`, `stack`, `min_experience`, `vacancies` | проверка соответствия пользователя |
| `Team` | `id`, `name`, `creator`, `description`, `roles`, `members` | роли, участники и свободные места |
| `TeamMember` | `user`, `role` | связь пользователя и роли в команде |
| `Application` | `id`, `team`, `applicant`, `role`, `status` | отмена, принятие и отклонение заявки |

Объекты связаны между собой: команда хранит объект создателя, а заявка ссылается
на объекты команды, кандидата и роли. В ПР5 источником данных остаются JSON-файлы;
переход на Django ORM запланирован для следующих практических работ.

## Страницы веб-интерфейса

| URL | View-функция | Назначение |
| --- | --- | --- |
| `/` | `homepage.views.index()` | главная страница и навигация |
| `/teams/` | `teams_web.views.teams()` | список команд и свободных ролей |
| `/teams/<int:team_id>/` | `teams_web.views.team_detail()` | карточка команды, роли и участники |
| `/applications/` | `applications_web.views.applications()` | список заявок и их статусы |
| `/applications/<int:application_id>/` | `applications_web.views.application_detail()` | карточка заявки и связанные объекты |

Для неизвестного идентификатора страницы команды или заявки возвращается ответ
с кодом HTTP 404. Все страницы имеют общую навигацию и оформлены Bootstrap 5.3,
подключённым через CDN. На этом учебном этапе HTML формируется view-функциями;
шаблоны будут подключены в следующей работе.

## Структура проекта

```text
teamsFrameworkePractic/
├── manage.py
├── teamfinder/          # настройки и корневые URL Django
├── homepage/            # главная страница и общий HTML-каркас
├── teams_web/           # веб-страницы команд
├── applications_web/    # веб-страницы заявок
├── models/              # классы предметной области ПР3
├── data/                # JSON-хранилище
├── tests/               # автоматизированные тесты
├── main.py              # сохранённая консольная версия
├── storage.py           # загрузка и сохранение связанных объектов
├── users.py
├── teams.py
└── applications.py
```

Имена `teams_web` и `applications_web` отделяют Django-приложения от модулей
предметной логики `teams.py` и `applications.py`, сохраняя код ПР3 без переноса и
дублирования.

## Реализовано

- создание и просмотр пользователей в консольной версии;
- создание, поиск и сортировка команд;
- добавление ролей и проверка свободных мест;
- проверка стека и опыта кандидата;
- подача, отмена, принятие и отклонение заявок;
- восстановление связей объектов при загрузке из JSON;
- Django-проект и три подключённых Django-приложения;
- двухуровневая URL-маршрутизация и динамические URL;
- главная страница, списки и карточки команд и заявок;
- HTML-ответы, навигация и адаптивное оформление Bootstrap;
- обработка отсутствующих объектов с HTTP-кодом 404.

Создание и изменение объектов через веб-формы, аутентификация, шаблоны и Django
ORM на этапе ПР5 не реализуются.

## Запуск

Требуется Python 3.10 или новее.

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py check
python manage.py runserver
```

После запуска веб-интерфейс доступен по адресу
`http://127.0.0.1:8000/`.

Консольная версия ПР3 по-прежнему запускается командой:

```bash
python main.py
```
